# Diorama: From Theory to Implementation (original brainstorm)

> Original brainstorm from a claude.ai discussion on 2026-10-21, kept unchanged for reference.
> The living plan is [../plot.md](../plot.md). Where they differ, plot.md wins.

## 1. Vision
Diorama is an open source tool that turns a software idea into an AI-generated 3D prototype of the finished product, then builds that prototype up piece by piece as the team ships work. It replaces flat Kanban boards and Gantt charts with a living miniature world that a manager, developer or client can understand at a glance.

## 2. Problem
- Kanban boards and Gantt charts show tasks, not the product. You can't see the whole thing you're building.
- Architecture diagrams (C4, UML) are technical and static, and they quickly drift away from what's really happening in sprints.
- Non-technical stakeholders find it hard to tell how far along a project is or how the parts fit together.

## 3. Core idea
1. The user describes what they're building.
2. An AI agent asks follow-up questions and breaks the product into modules (auth, catalogue, cart, payments, and so on).
3. Each module is mapped to a **domain metaphor** taken from the business's own world. For example, an e-commerce app becomes a shop.
4. The finished product is shown first as a ghost prototype. As each sprint's work gets done, its pieces become solid and slot into place.
5. Data flow is animated between pieces, so you can see how information moves through the system.

## 4. Research gap
| Existing work | What it does | Limitation |
|---|---|---|
| CodeCity (Wettel & Lanza) | Shows existing code as a 3D city | Only after the code exists; generic shapes |
| Gource | Animates repo history | Only past commits, no product view |
| Kanban / Jira / Gantt | Tracks tasks and time | Flat and abstract, no product shape |
| C4 / Structurizr | Architecture diagrams | Technical, static, not linked to progress |

**Gap:** As far as we know, no tool brings together (a) a prototype of the *planned* product shown before it's built, (b) a *domain-specific* metaphor generated by AI, and (c) *live* links to sprint progress and data flow.

Possible research questions:
- RQ1: Do domain metaphors help stakeholders understand project status better than Kanban boards do?
- RQ2: Can a large language model reliably turn a backlog into a coherent spatial metaphor?
- RQ3: Does seeing data flow help teams find integration problems earlier?

## 5. Pilot domain: e-commerce shop
| Software module | Shop metaphor |
|---|---|
| Authentication | Entrance door / security desk |
| Product catalogue | Shelves |
| Search | Store directory / signage |
| Cart | Shopping trolley |
| Checkout & payments | Checkout counter |
| Inventory | Back warehouse |
| Orders & shipping | Loading dock and delivery van |
| Admin dashboard | Manager's office |

Data flow example: a parcel moves from the shelf to the trolley, then the counter, the warehouse and finally the van.

## 6. Architecture
1. **Connectors**: GitHub first (Issues, Milestones, PRs, webhooks), with Jira later. Milestones act as sprints.
2. **Agent layer**: an LLM that interviews the user, reads the backlog and maps features to metaphor zones. It outputs a scene schema.
3. **Scene schema (core)**: a JSON spec of zones, the parts inside them, their status (planned, in progress, done), linked issues, and the data-flow edges between zones. Themes can be plugged in, so the community can add hospital, bank or delivery themes.
4. **3D viewer**: React Three Fiber on Three.js, running in the browser. Ghost outlines become solid as work finishes. Click a zone to inspect it.
5. **Sync service**: listens to webhooks, updates part status and pushes changes to the viewer.

Suggested stack: TypeScript monorepo, Next.js, React Three Fiber, a Node backend, the Claude API for the agent, and SQLite or Postgres.

## 7. Scene schema sketch
```json
{
  "theme": "ecommerce-shop",
  "zones": [
    {"id": "auth", "metaphor": "entrance", "status": "in_progress", "issues": [12, 14], "sprint": 1},
    {"id": "catalogue", "metaphor": "shelves", "status": "planned", "issues": [20], "sprint": 2}
  ],
  "flows": [
    {"from": "catalogue", "to": "cart", "label": "add item"}
  ]
}
```

## 8. MVP (v0.1)
1. GitHub OAuth, then pick a repo, then import issues and milestones.
2. Idea interview with the agent, which proposes a module-to-zone mapping the user can edit.
3. Shop scene with five zones: entrance, shelves, cart, checkout, warehouse.
4. Live progress: closing an issue makes its part solid.
5. Click a zone to see its issues, assignees and progress.

## 9. Roadmap
- **v0.2**: Animated data flow between zones.
- **v0.3**: Jira connector.
- **v0.4**: Theme SDK and a community theme library (hospital, bank, food delivery).
- **v0.5**: Timeline scrubber to replay the build sprint by sprint.
- **Research track**: user study comparing Diorama with Kanban (RQ1 to RQ3).

## 10. First steps in Claude Code
1. Create the `diorama` repo with a monorepo layout (`apps/web`, `apps/server`, `packages/schema`, `packages/themes`).
2. Define the scene schema types and validation first.
3. Build a static shop scene from a hand-written schema.
4. Add the GitHub connector and status sync.
5. Add the agent interview and mapping.
